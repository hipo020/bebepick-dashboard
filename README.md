# Bebepick Dashboard

베베픽 재고를 모바일에서 보기 위한 정적 웹페이지입니다.

- 실제 감시/DB: Supabase `schedule-app`
- 백엔드 함수: `bebepick-dashboard`
- 화면: GitHub Pages
- 1분 자동 갱신
- 검색 / 판매중·품절·숨김 필터
- 재고 적은 순 / 많은 순 / 이름순
- 상품 이미지 / 가격 / 풀박스 가격 / 재고 표시

이 저장소에는 비밀키를 저장하지 않습니다.

## GitHub Pages

Repository Settings → Pages에서
- Source: Deploy from a branch
- Branch: main
- Folder: /(root)

로 한 번만 설정하면 됩니다.

예상 주소:
https://hipo020.github.io/bebepick-dashboard/


## 개인용 공식 주문번호 발급 (주문 생성은 명시적 최종 확인 후에만)

- 재고판 장바구니에서 낱개/풀박스, 여러 종류 및 수량을 선택할 수 있습니다.
- 발송/보관 + 미개봉/개봉/카드개봉 옵션을 확인할 수 있습니다.
- 공식 홈페이지 소스와 동일하게 상품 합계 70,000원 이상일 때 요청 배송비 0원, 미만일 때 4,000원을 더해 `create_web_order` RPC에 전송합니다. **실제 입금액은 판매자 카카오톡 안내를 우선합니다.**
- 최종 주문 생성은 버튼 클릭 후 상품/옵션/금액 확인창 승인으로만 실행됩니다. 자동 주문이나 자동 재시도는 없습니다.
- 발급 번호에 `set_web_order_customer_memo` RPC로 발송/보관·개봉 옵션을 저장합니다. 메모 저장 실패 시 기존 번호로 메모만 재시도하며 주문 자체를 재생성하지 않습니다.
- 별도 Supabase Edge Function `bebepick-personal-checkout`이 외부 공식 RPC 두 개만 처리하고, 자체 비공개 테이블 `bebepick_order_attempts`로 사용자 요청 idempotency 및 불확실한 주문 응답을 관리합니다.
- 빠른 주문을 위해 추가 개인 주문 연동키 및 잠금 비밀번호 단계를 제거했습니다. **공개 재고판을 이용하는 사람도 공식 서버 규칙 내에서 주문번호 생성 요청을 할 수 있습니다.** 이는 별도 사용자 인증이 없다는 의미이며, 판매자 자체 방송·재고·주문 검증 및 요청 중복 방지는 유지됩니다.
- 외부 Supabase 계정/프로젝트의 테이블을 직접 변경하지 않습니다. 요청은 사용자 승인 후 공식 주문 RPC만 호출합니다.
- 개발 중 실제 판매자 주문은 생성하거나 테스트하지 않았습니다. CORS/권한/실제 주문 동작 검증은 첫 사용자 승인 실주문 시에만 가능합니다.
- 장바구니 및 발급한 주문번호는 브라우저의 `localStorage`에 저장됩니다. **주문 생성 중 페이지를 종료하거나 HTTP 요청이 불확실하면 재주문하지 말고 기존 주문번호 및 고객센터를 확인해야 합니다.**
- 코드만으로는 실주문 처리 속도 및 판매자 서버 동작을 보장할 수 없습니다.

## 추가 주문 연동키 제거 및 개인 주문내역 삭제

- 추가 연동키 입력·비밀번호 설정·잠금 해제 UI가 없습니다. 기존에 이 기기 브라우저에 저장된 암호화 키는 더는 사용되지 않습니다. 필요하면 해당 사이트 데이터를 삭제해 정리할 수 있습니다.
- 공개 GitHub Pages 주소의 방문자는 동일한 결제전 공식 주문번호 생성 흐름에 접근할 수 있습니다. 별도 사용자 계정 인증 기능은 없습니다.
- 기존 개인 주문저장소(`bebepick_saved_orders`)를 Edge Function `bebepick-dashboard?api=orders`에서 GET/POST/DELETE로 제공합니다. 기존 개인 연결코드의 SHA-256 해시를 이용하여 해당 사용자 목록만 조회하고, 테이블은 RLS 및 일반 클라이언트 직접 권한 차단 상태입니다.
- `내 주문내역`의 개별 **삭제**는 개인 저장소의 해당 주문만 삭제하고, 이 기기의 발급번호 표시도 함께 삭제합니다. **베베픽 판매자 서버의 실제 주문은 취소·삭제되지 않습니다.**
- 삭제한 주문번호를 다시 명시적으로 조회하면 저장목록에 재등록될 수 있습니다.

## 크림·로즈 모바일 디자인 및 숨김 재고 장바구니

- 삼성 인터넷 다크모드가 페이지 배경과 선택색을 의도치 않게 변형하는 문제를 줄이도록 `color-scheme: only light`와 크림/로즈 색상 토큰을 적용했습니다. 브라우저의 강제 다크 기능에서는 여전히 결과가 다를 수 있습니다.
- 재고 상품 카드/장바구니/주문 최종 확인/내 주문 조회의 간격, 버튼 크기, 텍스트 대비와 터치 영역을 정돈했습니다.
- **숨김이면서 실제 재고가 남고 단가가 유효한 상품**은 낱개·풀박스를 개인용 장바구니에 담을 수 있습니다. 해당 카드에는 숨김·재고 상태가 별도 표기됩니다.
- 숨김 상품도 재고와 공식 등록 가격이 유효하다면 **판매중 상품과 동일하게 공식 주문번호 생성 요청을 보낼 수 있습니다.** 재고판과 사용자 소유 주문 서버의 `shop_products.visible` 필터는 적용하지 않습니다. 하지만 베베픽 공식 `create_web_order` 요청의 수락 여부는 공식 서버에서 결정합니다.
- 상품 저장/삭제, 재고 조회, 최종 주문 확인 및 발급 후 상태 복구는 종전 로직을 유지합니다.
- 판매자 시스템의 숨김 설정, 상품 상태나 재고 데이터 자체를 변경하지 않았습니다.

## 숨김 상품 공식 주문 요청 주의사항

- 판매중 여부를 프런트엔드/개인용 백엔드에서 제한하지 않으며, 숨김 상품도 **재고·가격 검증 후** 사용자가 최종 확인할 때만 공식 주문번호 생성 API에 전달합니다.
- **베베픽 공식 서버의 정책이나 권한을 우회하지 않습니다.** 숨김 주문이 실제로 허용되는지는 공식 서버의 결과에 따라 달라집니다.
- 기존 상품 재고/가격 검증 및 중복 주문 방지, 주문번호 저장, 옵션 메모 복구는 그대로 유지합니다.
- 재고판과 주문 API는 **추가 사용자 인증이 없는 공개 페이지/엔드포인트**입니다. 따라서 외부 방문자도 숨김 상품 주문번호 생성 요청을 시도할 수 있습니다. 직원 전용 용도라면 별도 접근 제어를 반드시 검토해야 합니다.
- 사용자 요청에 따라 자체 서버의 숨김 필터를 제거했지만, **베베픽 공식 데이터와 주문은 테스트로 쓰거나 생성하지 않았습니다.**
