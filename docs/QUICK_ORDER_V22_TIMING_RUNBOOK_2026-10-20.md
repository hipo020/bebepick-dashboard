# 공식 홈페이지 범용 빠른 주문 v2.2 · 속도 기록 인수인계 (2026-10-20)

## 무엇을 변경했나

- **기존 소스 파일은 유지**: `bebepick-quick-order-general-v2.js` (v2.2 구간별 속도 측정 기능 추가). `v1` 및 밤토끼 D796 전용 v4/v5, Android 주문 도우미, Supabase 30초 YouTube 감시는 변경하지 않음.
- 설치 안내: `bebepick-quick-order-v22-install.html`. 새 북마크는 `?v=20261020-v22-timing`을 써서 캐시를 구별함.
- 사용 장소: 판매자 공식 `https://bebepick.me/live`, `https://bebepick.me/plus` (새 베베픽 개인 주문 대시보드와 별개).
- `⏱️ 자동주문 구간별 속도 기록 (로컬 저장)` 펼침 패널로 이벤트, 감시 표본, 조회 시간 범위, 재고 발견 → 주문 확인 버튼까지 측정한 시차를 표시함.
- 실행별 이벤트는 `performance.now()`(단조 증가)로 측정, 날짜 문자열은 참고용 UTC 시각. 수치 표시는 밀리초 소수 첫째 자리.
- `sessionStorage['bbp_general_v2_timing_last_'+STORE]`에 **같은 탭의 마지막 진단 기록**을 약 300ms 지연 저장하고 새로고침 시 읽음. 기록이 필요하면 `JSON 저장` 또는 `기록 복사`로 직접 보관.
- 수집하지 않는 항목: 로그인 토큰, 쿠키, 주문번호, 결제창 본문, 고객 이름, 결제 완료 여부, 서버 주문 성공 판정.
- **별도 서버 알림/업로드/폴링이 추가되지 않음**. 기존 공식 RPC `list_products`, `order_windows`의 호출 횟수와 5/8/10/15/30/60초 감시 간격을 그대로 둠.

## 단계별 기록 의미

| 이벤트 키 | 정확한 기준 |
| --- | --- |
| `started` | 상품·옵션을 선택한 뒤 ‘대기 시작’을 누르고 주문 설정 확인을 마친 시각 |
| `initial_cart` | 최초 표시된 공식 목록 기준 준비 (새 서버 확인 전의 캐시일 수 있음) |
| `first_poll` | 공식 `order_windows` + `list_products` 병렬 조회 시작 |
| `poll_sample`, `poll_error` | 처음/10회마다 또는 오류 시 조회 전체 왕복 소요 시간, 전체 횟수와 RPC별 통계 |
| `sellable` | **새로 받아온 `list_products` 응답**에서 선택 SKU가 판매 가능하다고 처음 관측한 시각 |
| `window_open` | **새로 받아온 `order_windows` 응답**에서 접수 ON 또는 사이트 LIVE 플래그를 처음 본 시각 |
| `cart_ready` | 옵션과 수량이 기대값대로 준비된 시각 |
| `both_ready` | 재고와 주문 접수/LIVE 조건이 같은 확인 주기에서 충족됐다고 판정한 시각 |
| `official_ui_wait`, `route_refresh` | 서버 응답에 비해 공식 페이지의 화면 반영이 늦어 기다리거나 자체 경로 갱신을 시도한 시각 |
| `official_ui_ready` | 공식 사이트 화면의 상품·구매 버튼 조건이 맞았던 시각 |
| `cart_click` | 장바구니 진입을 위한 **DOM 클릭 함수 호출** 시각. 서버 접수 보증 아님 |
| `cart_panel`, `option_ok` | 공식 장바구니 패널 및 개봉·보관 옵션 확인 시각 |
| `checkout_click` | 공식 확인창 이동 버튼의 **DOM 클릭 함수 호출** 시각. 주문 생성 아님 |
| `confirm_visible`, `agree_step1`, `final_visible` | 공식 확인 대화상자 등장과 1·2단계 진행 표시 |
| `dry_run_stop` | 무전송 시험에서 **최종 주문 클릭 없이** 중단한 시각 |
| `submit_click` | 사용자가 실주문 별도 동의한 경우의 최종 클릭 호출. **서버 접수/주문번호 확인과 다름** |
| `pay_panel`, `pay_click` | 별도 사용 허용된 결제창 표시와 PayApp 버튼 호출. **결제 승인 기록 아님** |
| `hidden`, `resumed`, `stopped`, `safety_stop` | 브라우저 숨김/복귀, 사용자가 중지, 안전장치 중단 |

**중요:** `sellable`은 실제 재입고가 발생한 시각이 아니라 **도우미의 첫 확인 시각**이다. 표시된 구간의 `재고 확인 후 Xms`도 그 시간부터 계산한다. `window_open`은 실제 유튜브 방송 시작과 동일하지 않을 수 있다. 전체 주문 접수 시간은 아직 실전에서 검증되지 않았다.

## 안전 및 테스트

- UI 초기 설정: 실주문 자동 클릭 OFF, `무전송 시험` ON, PayApp 이동 OFF.
- 실주문을 위해서는 기존대로 자동 클릭 체크, 무전송 OFF, 실제 주문 생성 명시 동의가 필요하며 이 변경에서는 해당 로직을 수정하지 않음.
- 표준 무전송 자동 확인 시나리오: ‘자동 클릭’ ON + ‘무전송 시험’ ON, 실제 최종 주문 클릭 0회 (공식 UI 확인용); 사용자가 직접 최종 클릭하면 그 작업은 별개이므로 주의.
- 기존 중복 요청 3분 방지 세션 키 `bbp_general_v2_submit_...`, 다른 주문의 개봉/보관 변경 경고 중단, 페이지 백그라운드 시 자동 진행 중단은 유지.
- 기존 `tests/general-fast-order-v2.test.mjs` **13개 모의 테스트**, 신규 `tests/general-fast-order-v22-timing.test.mjs` **4개 시간 기록 테스트**.
- 실상품 재입고 후 공식 페이지의 동작은 사용자가 동의하는 실전까지 확인되지 않았음. 소스 모의 테스트 성공을 실전 주문 성공으로 취급하지 않기.

## 향후 개선 시 확인할 것

- 범용 북마크가 구버전 v2.1 패널과 동시에 떠 있으면 반드시 공식 페이지를 새로고침한 후 새 v2.2 북마크를 실행.
- 병목 비교 시 `list_products`와 `order_windows`의 RPC 통계 vs `official_ui_wait` → `official_ui_ready` → `checkout_click` 사이 시간으로 구분.
- 판매자가 실시간 WebSocket 신호를 제공한다는 증거는 2026-10-20 공식 app.js 읽기 진단에서 찾지 못했지만, 이를 근거로 서버 전체에 실시간 API가 없다고 단정하면 안 됨.
- 이 기록 패널은 자동으로 서버에 파일을 전송하지 않음. 사용자가 `JSON 저장` 또는 `기록 복사`로 제공한 경우에만 분석.


## 2026-10-20 v2.2.1 추가: 공식 장바구니 화면 진입 지연 최적화

- 기존 v2.2 타이밍 기록과 품절 감시, 상품·주문 조건의 공식 서버 검증은 그대로 둠.
- **상품 RPC 조회 간격은 변경하지 않음**: D796 등 사용자 선택 5/8/10/15/30/60초 설정 그대로.
- 재고/접수 조건 충족 후 공식 주문 버튼을 클릭하면, 종전 100ms 간격 카트 패널 검사 대신 **DOM 변경 즉시 검사 + 50ms 간격 백업 검사**.
- 즉시 생성된 공식 카트 패널은 `queueMicrotask`로 첫 100ms 대기 없이 처리할 수 있음.
- DOM 변경 연속 이벤트로 **개봉/보관 선택 버튼이 반복 토글되지 않게** 40ms 검사 간격 제한.
- 장바구니 미표시, 옵션 불일치, 비활성 주문 버튼 등 안전 조건은 종전대로 중단. 총 최대 대기 시간 2500ms를 유지. 장바구니 상품/수량 불일치 시 최종 진행 중지.
- 실제 최종 주문 클릭 여부, 명시 동의, 무전송 기본값, 3분 중복 요청 보호, PayApp 결제창 열기 조건은 **전혀 변경하지 않음**.
- 북마크 JS 내부 버전은 `2.2.1`, 설치 HTML 주소는 동일한 `bebepick-quick-order-v22-install.html`, JS 캐시 구분 파라미터는 `?v=20261020-v221-fast-cart`.
- 이미 v2.2 창이 열려 있으면 공식 페이지를 **새로고침한 뒤 v2.2.1 설치 코드로 다시 실행**. 기존 진행 중인 주문을 중복 실행하지 않도록 같은 탭 버전 검증.
- 추가 `tests/general-fast-order-v221-dom.test.mjs` 6개. 기존 13개 주문·옵션 보호 + v2.2 계측 4개 포함 총 23개 모의 테스트.
- 성능 개선은 **사이트 DOM이 빠르게 나타나는 경우의 이론적 대기 감소**이며 실제 서버·재입고/결제 시각은 아직 미검증.
