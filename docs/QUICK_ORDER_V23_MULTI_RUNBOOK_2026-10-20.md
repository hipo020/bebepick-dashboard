# 베베픽 공식 홈페이지 범용 빠른 주문 v2.3 · 여러 인형 묶음 주문 및 자동 스크롤 (2026-10-20)

## 개발 목표와 사용자 요청

- "여러 개 구매! 없다면 있는 것만!"
- 여러 인형 SKU 등록, 재고가 열린 상품만 한 번의 공식 주문 장바구니에 담기. 모든 상품의 재고가 열릴 때까지 기다리지 않음.
- 공식 주문창/확인창이 떴을 때 기존 고정된 긴 도우미가 화면을 덮던 문제 해결: 주문 진행 시 작은 상단 버튼으로 접고, 다음 공식 클릭 대상까지 화면 이동.
- 기존 D811 실제 자동주문 타이밍 JSON: 2026-10-20 `sellable=12:16:14.810Z`, `submit_click=12:16:14.933Z`, 관측 간격 **123.1ms**. 이것은 서버 주문 접수 성공을 확인한 시간은 아님. 사용자 첨부 녹화는 주문 확인창 뒤에 긴 도우미가 가리다가 공식 PayApp 화면으로 넘어가는 모습이 보임. 결제 승인은 녹화로 확인되지 않음.
- 사용자가 원한 간결한 UI: 기존 검색·목록·수동 SKU 코드/구매 단위 컨트롤을 접이식 **＋ 인형 추가** 안으로 넣고, 감시 목록을 각 상품 2줄로 표시.

## 동작 — 한 서버 조회로 모든 SKU 감시

1. `watchItems`에 최대 10개 SKU 등록. 중복 SKU는 금지, 각 SKU 별 낱개 1개 또는 풀박스 1세트 옵션 선택. 저장 키 `bbp_general_v23_watches_<STORE>`; v2.2.1에서 저장한 단일 SKU는 초기 감시 후보로 가져오되 기존 선택과 구성을 바꾸지 않음.
2. 조회 주기 5/8/10/15/30/60초는 기존 사용자 설정 유지. **등록 상품 수와 무관하게** 각 라운드의 RPC는 `order_windows` + `list_products(p_brand:STORE)` 각각 1회 병렬 호출.
3. 공식 상품 RPC에서 매 SKU의 `stock` 및 `fullbox_out`, 해당 몰 판매 여부, 풀박스 지원/1인 제한 등을 개별 확인. 품절·목록에 없는 코드는 후보 제외. 공식 주문 접수 / LIVE 표시가 가능하다고 판단될 때, **그 라운드에 구매 가능한 상품만** `armedItems`에 동결.
4. 이미 장바구니에 다른 항목이 있다면 **대기 시작 전에** 현재 몰 항목을 앞으로 구매 가능한 SKU 묶음으로 교체할 수 있음을 별도 확인. 사용자가 거부하면 대기 시작 안 함. 다른 몰 카트 항목은 건드리지 않음.
5. 상품이 없을 때는 카트 변동 없이 감시. 상품이 있다면 `armedItems`의 각각 `{sku,opt,qty:1,store:STORE,lid}`를 공식 `bbp_cart_v1`에 넣고 기존 공식 `StorageEvent`를 사용해 UI 반영.
6. 주문 UI 이동 전에 **전체 묶음의 SKU·낱개/풀박스·수량·같은 몰의 추가 항목 부재**를 재검증. 공식 사이트 카드마다 품절이 아닌지도 모두 확인. 하나라도 어긋나면 자동 진행 안 함.
7. 같은 공식 주문 한 건의 확인 2단계로 진행하며 최종 클릭은 기존 one-shot 보호로 **최대 1회만**. 여러 개를 따로 연속 주문하는 기능이 아님. 주문 결과가 불확실하면 임의 재시도하지 않음.

### 현재 한계

- 베베픽 공식 주문 확인창의 **개봉·보관/발송은 전체 주문에 공통 적용**하는 구조. 각 인형마다 다른 개봉/보관 설정을 하나의 주문에서 지원하는 것으로 가정하지 말 것.
- 다른 상품들이 추가로 재입고되더라도 **첫 구매 가능한 묶음을 발동한 후에는 더 주문하지 않음**. 보유/재고가 불안정하면 실제 서버에서 제외되거나 거절될 수 있고, 사이트를 우회하지 않음.
- 실전 다중 SKU의 실제 주문번호 생성 및 결제 성공은 아직 확인되지 않음. 소스 테스트 성공을 실거래 성공으로 설명하면 안 됨.
- Android Kakao 자동주문, Supabase 30초 YouTube 폴링, ntfy, FCM, WebSub, 개인 재고판 등과 **독립적**.

## 주문 확인창 가림 해결

- `foldForOfficial()`: 공식 카트 버튼이 실제 활성화되어 진입할 때 큰 floating `aside`를 숨기고 상단 우측 작은 **🧸 … · 펼치기** 버튼으로 대체.
- `revealOfficialStage()`: 화면에 존재하는 공식 `#checkout`, 1단계 `[data-oc="next"]`, 최종 `[data-oc="ok"]`, PayApp 이동 `[data-act="pay-card"]` 순으로 실제 존재하는 클릭 대상의 위치로 `scrollIntoView({block:'end',behavior:'auto'})`. 이 기능은 **클릭하지 않고 스크롤만** 함.
- 공식 DOM 단계 변경 시만 다시 스크롤하며 사용자가 작은 버튼을 눌러 긴 도우미를 다시 열 수 있음. 자동으로 결제 승인하지 않음.
- 버튼이 비활성화된 경우/옵션이 다르거나 다른 주문의 보관/발송 전환 경고가 나타나는 경우는 기존대로 안전 중단.

## 테스트/운영

- 모의 테스트: 7개 구조/정책 + 4개 실제 fake cart 준비 테스트로 11개. 기존 v2.2.1 테스트 23개와 합쳐 CI 총 34개 실행하도록 구성.
- `tests/general-fast-order-v23-multi.test.mjs`의 fake cart에서는 두 상품이 가능한 경우 한 번의 `localStorage.setItem`, 다른 몰 장바구니 보존, 미동의/재고 상실 시 쓰기 0회를 확인.
- **무전송 시험 ON이 기본**, 자동 최종 클릭 OFF, PayApp 이동 OFF. 실주문을 원하면 사용자 본인이 주문 설정을 변경하고 실제 주문 생성에 명시 동의해야 함.
- 브라우저 백그라운드로 가면 타이머 지연/감시 중단 가능. 중요한 시간엔 해당 탭을 전면에 두기.
- v2.2.1 도우미와 동시에 실행하지 않기. 전환 시 기존 도우미 대기 중지, 공식 페이지 새로고침, v2.3 북마크 실행.
- 문제가 있다면 v2.3을 더 실행하지 않고 **기존 [v2.2.1 설치 페이지](https://hipo020.github.io/bebepick-dashboard/bebepick-quick-order-v22-install.html)**를 이용해 이전 단일 주문 방식으로 복귀할 수 있음.

## 추가 보호 — 대기 중 장바구니 변경 감지

- 사용자가 대기를 시작할 때 해당 몰 장바구니 SKU·구매단위·수량·줄 ID의 스냅샷을 보관함.
- 구매 가능 신호가 와도 그 사이 기존 장바구니가 변경됐다면 새 묶음으로 덮어쓰지 않고 **안전 중지**.
- 모든 대상 상품이 구매 가능하지 않아도 첫 판매 가능 후보 묶음을 확인하는 즉시 나머지 품절 SKU를 제외하고 진행.
- 모의 테스트에서 대기 도중 같은 몰 장바구니에 새 제품을 추가한 경우 주문 준비 시 쓰기 0회 확인.
