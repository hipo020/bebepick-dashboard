🧸 베베픽 자동주문 v2.4 · 이름 후보 / 여러 SKU

미공개 신상 이름 후보 20종 중 먼저 판매 가능한 1종 주문 또는 기존 SKU 여러 개 함께 주문

한 몰에서 여러 인형/낱개·풀박스/수량을 고른 다음, 공식 재고가 모두 준비될 때까지 기다려. 개봉·보관 옵션을 미리 정해 두고, 명시 동의한 경우에만 공식 주문 확인과 주문 생성까지 진행해. 기본값은 PAYAPP 이동 없이 멈춰. 별도 동의가 있으면 공식 주문번호 생성 후 공식 결제하기 버튼을 1회 눌러 PAYAPP 페이지 열기를 시도하지만, 실제 결제 승인은 자동으로 하지 않아.

🦊 갤럭시 Firefox 원터치 실행 (시험판)
크롬 주소창에서 북마크를 검색하는 대신, Firefox + Tampermonkey에서 베베픽 공식 주문 페이지를 열면 🧸 주문 도우미 버튼이 화면에 나타나. 버튼을 직접 눌러야 기존 v2.4 도우미를 불러오며, 실제 감시/주문/결제를 자동 시작하지는 않아.
① Firefox용 Tampermonkey 설치 → ② 원터치 버튼 사용자 스크립트 설치 → ③ Firefox에서 베베픽 플러스 또는 베베픽을 열고 🧸 주문 도우미 한 번 눌러.
버튼이 안 보일 때: Firefox 확장 기능 → Tampermonkey → 대시보드에서 베베픽 v2.4 · Firefox 원터치 실행이 설치되고 켜져 있는지 먼저 확인해. PAYAPP 결제수단 선택 도우미와는 별도 설치야. 베베픽 화면에서는 v1.1.0부터 버튼이 왼쪽 가운데에 나타나고, 페이지가 다시 그려져도 버튼을 복구해. 새 버전 설치 후 베베픽 페이지를 다시 열어 줘.

💳 카드결제 시험: Firefox 설정의 ‘결제 수단 저장 및 자동 입력’ 기능이 한국 기기에서 제공된다면 브라우저 자체 보안 저장소로만 설정해. PAYAPP 결제창에서 카드 자동완성/간편결제가 실제로 작동하는지는 별도 확인이 필요해. 우리 스크립트는 카드번호·유효기간·CVC를 읽거나 저장하거나 입력하지 않아. 최종 결제 승인은 직접 진행해.

💳 Firefox PAYAPP 결제수단 선택 도우미 (선택 설치 · 시험판)
✅ 사전 설정 v0.3.0: 베베픽 주문이 닫혀 있어도, 같은 Firefox에서 먼저 도우미를 설치한 뒤 PAYAPP 공식 홈페이지의 사전 설정 패널로 들어가. 기본 결제수단: 카드번호 직접입력을 선택하고 다음 결제부터 결제수단 경로 자동 선택을 켠 다음 설정 저장을 누르면 돼. PAYAPP 공식 홈페이지와 결제화면은 같은 payapp.kr 도메인이므로 선택값과 ON/OFF만 같은 Firefox 브라우저 저장소에 저장돼. 첫 주문에서도 별도 결제 도우미 열기가 필요 없어. 홈페이지에서 설정 버튼이 나타나지 않으면 Firefox에서 Tampermonkey 스크립트가 v0.3.0으로 업데이트되고 켜져 있는지 확인해.
기본은 카드번호 직접입력이고, ISP/안심클릭·네이버페이·카카오페이·토스페이·스마일페이·페이코·애플페이·계좌이체로 바꿀 수 있어.
Firefox + Tampermonkey에서 PAYAPP 결제 경로 선택 도우미 설치를 눌러 별도 사용자 스크립트를 설치해 줘. 공식 PAYAPP 결제 페이지에서 💳 결제 방식 버튼을 누르고 선호 방식을 선택한 다음, 화면을 확인해 현재 화면에서 선택한 경로로 이동을 직접 눌러. 더 빠른 자동 선택 v0.3.0: 결제창에서도 직접 설정할 수 있지만, PAYAPP 공식 홈페이지에서 결제 전에 미리 설정하는 것을 권장해. 이후 PAYAPP에 도착할 때마다 도우미를 열 필요가 없어. 약관 동의는 직접 하고, 그다음 공식 결제방식 선택 화면부터 기본 카드 직접입력 경로를 최대 단계별 1회 자동 선택해. 선호 결제방식은 나중에 변경할 수 있어. PAYAPP의 다른 가맹점 결제에도 이 설정이 적용될 수 있으니 원치 않으면 자동 선택을 꺼 줘. PAYAPP 화면에서 항목을 정확하게 한 개 찾았을 때만 1회 이동을 시도하고, 찾지 못하면 직접 골라야 해. 전자금융거래 약관 동의·카드정보 입력·본인인증·최종 결제 승인은 자동으로 하지 않아.

버튼이 안 보이면? PAYAPP 페이지가 Firefox 앱에서 열린 건지 확인해. Firefox ⋮ → 확장 기능 → Tampermonkey가 켜져 있는지, Tampermonkey 목록에서 베베픽 · PAYAPP 결제수단 선택 도우미를 실제 설치·활성화했는지 확인하고, PAYAPP 페이지를 새로고침해. v0.1.1부터 💳 버튼은 화면 왼쪽 위에 표시해, 오른쪽 영상 팝업과 겹치지 않게 했어. 단, 결제창에서 새로고침하면 결제 세션이 초기화될 수 있으니 주문번호·결제 상태를 먼저 확인해.
이 스크립트는 payapp.kr의 결제 경로 페이지에만 적용되고, 카드번호·유효기간·CVC·비밀번호·생년월일을 읽거나 저장하지 않아. 선택한 결제 방식의 이름만 브라우저에 저장돼. Firefox의 내장 카드 자동완성을 사용할 수 있다면 별도 설정하고, PAYAPP의 분리된 입력칸에서 실제 작동하는지는 확인해 줘. 기기에서 결제 성공까지 검증되지 않았고, PAYAPP 화면 구조가 다르면 자동 선택이 동작하지 않을 수 있어.

지원하는 세 감시 방식

🧸 새 통합 모드: 기존 SKU(총 5개 등) 전부 + 신상 이름 후보 중 확인된 한 종류를 함께 주문 준비해. 기본은 무전송 시험이야. 별도로 PAYAPP 이동을 선택하고 시작 시 승인한 경우에만 실제 주문번호를 만들고 PAYAPP 이동을 시도해. 현재 브라우저 장바구니 5개가 도우미 SKU 목록에 없다면 `장바구니를 기존 SKU 목록으로 가져오기`를 눌러 확인한 다음 통합을 선택해.

🔎 모바일 UI 정리: 이름 후보와 기존 SKU는 별도 저장 목록이야. 두 화면을 동시에 주문하지 않고, 선택한 감시 방식만 주문 대상으로 사용해. 화면 아래 기존 SKU 목록과 이 브라우저에 저장된 사이트 장바구니를 따로 확인할 수 있어. 이전 북마크는 반드시 새 코드로 교체해 줘.

① 이름 후보 중 1종 주문: 공식 SKU를 몰라도 인형 이름을 20종까지 미리 등록해. 이름이 띄어쓰기 제외 정확히 일치하고 공식 매장/재고 조건이 맞는 상품 1종을 자동 선택해. 여러 후보가 한 번에 판매 가능하면 등록한 우선순위를 따라. 비슷한 이름은 일치로 보지 않아. 같은 이름의 SKU가 여러 개면 그 후보는 자동 선택하지 않아.

② 기존 여러 SKU 모두 주문: v2.3과 똑같이 상품코드를 지정하고 여러 인형·수량을 담아 선택 상품이 모두 판매 가능할 때 주문해. 이름 후보와 SKU를 합쳐 주문하려면 ③ 통합 모드를 사용해.

③ 기존 SKU + 신상 통합 주문: 현재 장바구니 수량을 확인하고, 등록한 기존 SKU 전부와 새로 발견된 이름 후보 중 한 종류를 함께 준비해. 중복 상품이나 수량 불일치 시 중단해.

📱 갤럭시 beta.37 원터치 연동: 기존 SKU/수량과 신상 이름 후보를 등록한 크롬 북마크에서 🚀 갤럭시 앱으로 인형 목록 한 번에 보내기를 누르면 앱을 열어 확인 후 저장해. 복사·붙여넣기 없이 설정만 전달하고 실제 주문을 생성하지 않아. 앱 설치가 먼저 필요해.

🧸 더 간결해진 모바일 북마크: 인형 수량·감시 방식·주요 시작 버튼은 그대로 보이고, 상품코드 직접 입력·PAYAPP 실제 주문 설정·PC 감시는 접어서 열 수 있어. 감시 주기 1·2·3·4·5·8·10·15·30초를 선택할 수 있어(60초 제거). 1~2초는 서버 요청 과부하·차단 위험이 있어 시작 시 추가 확인을 받아. 처음에는 3~5초를 권장해.

💙 PAYAPP 전체동의 → 다음 (별도 실행): 공식 PAYAPP 결제 페이지가 열리면 별도로 저장한 PAYAPP 동의 북마크를 주소창에서 찾아 실행해 줘. 약관을 읽고 확인하면 해당 화면의 전체동의(필요한 경우)와 다음을 각각 최대 1회 클릭하는 보조 기능이 실행돼. 결제수단·카드정보·결제 승인은 건드리지 않아. 베베픽에서 PAYAPP으로 넘어가면 자동 실행이 이어지지 않는 브라우저 보안 제한이 있어. 갤럭시에서 테스트되지 않은 결제창 구조면 자동 클릭 없이 중단할 수 있어.

🧸 자동/수동 클릭 구분: 주문 확인창에서 「네, 이대로 주문」을 손으로 눌렀는지도 별도 기록해. 로그의 submit_click은 클릭 명령일 뿐 주문 성공이 아니야. 실제 주문 확인은 공식 결제 화면/주문내역으로 확인해 줘. 중복 주문 방지를 위해 첫 클릭이 수락되어 확인창이 사라지면 자동 재클릭하지 않아. 첫 클릭이 수락되지 않아 같은 최종 확인창이 그대로 남아 있을 때만 900ms 이후 최대 1회 후속 클릭해.

🔎 「네, 이대로 주문」 진행 진단 강화: 공식 확인창이 자동 클릭 이벤트를 받더라도 서버 접수까지 이루어졌는지와는 별개야. 최종 버튼 자동 클릭 후 2초·5초에 공식 화면 변화 및 주문 요청 흔적을 읽기 전용으로 확인해 기록하고, 5초가 지나도 결제 화면이 확인되지 않으면 수동 확인을 안내해. 동일 버튼 자동 재클릭이나 직접 서버 주문은 하지 않아. 브라우저에 따라 네트워크 흔적이 수집되지 않을 수 있고 사이트 실제 클릭 정책은 별도 확인이 필요해.

🔎 최종 주문 읽기 전용 진단: 최종 주문 자동 클릭 직전·직후·2초·5초 시점의 공식 동의 체크 상태, 버튼 활성 여부, 확인창 유지 여부를 추가 기록해. 클릭 횟수나 주문/결제 동작은 변경하지 않아. 브라우저에서 확인되는 상태만 기록하므로 사이트 내부 주문 처리 성공을 보장하지 않아. 기존 베베픽 실행 북마크는 새 코드로 교체해 줘.

⏳ 최종 주문 버튼 공식 대기시간 준수: 사이트 app.js의 최종 확인 버튼은 확인창이 열린 뒤 700ms까지 클릭을 받지 않아. v2.4는 이 조건을 우회하지 않고 최종 동의 후 최소 700ms에 공식 버튼을 처음 누른 다음, 사이트가 동일한 확인창을 즉시 제거하지 않은 경우에만 900ms 이후 같은 버튼을 한 번 더 눌러. 첫 클릭이 정상 수락되면 두 번째 클릭은 없어. 네트워크가 느리거나 결제창이 늦다는 이유만으로 추가 클릭하지 않아. 기존 상품·수량·동의 확인, 무전송 기본값, 중복 방지, PAYAPP 승인 수동 정책은 유지돼. 실제 주문 생성은 공식 결제 화면 또는 주문 내역으로 확인해 줘.

설치 방법

  1. 아래 베베픽 실행 코드 복사를 눌러. 북마크 이름을 베베픽 실행으로 정해.
  2. PC·갤럭시 크롬에서 새 북마크를 만들고 북마크 주소를 복사한 코드로 바꿔.
  3. 베베픽 플러스 또는 베베픽 주문 페이지에 로그인해 둬.
  4. 갤럭시에서 북마크 목록을 눌렀을 때 아무 반응이 없다면 주소창에서 북마크 이름 검색 → 북마크 추천을 선택해 줘. 기존 v2.2.2 등 주문 도우미가 떠 있다면 공식 페이지를 한 번 새로고침하고, 새 v2.4 북마크를 실행해. 이전 실주문 v2.3과 진단 v2.3.1/v2.3.2를 같은 탭에서 동시에 사용하지 마.
  5. 감시 방식을 선택해. 이름 후보 모드라면 정확한 이름을 적고 후보 수량·낱개/풀박스를 정해 ＋ 이름 후보 등록을 반복해. 후보는 ↑↓로 우선순위 조정 가능해. 이미 진단 v2.3.2에 입력한 후보는 처음 실행 시 가져오지만 실주문 모드를 자동 ON하지는 않아.
  6. 기존 SKU 모드라면 인형 검색 → 구매 단위/수량 → ＋ 인형 추가로 여러 SKU를 목록에 담아.
  7. 개봉·보관 옵션을 선택해 (한 주문의 전체 상품에 동일하게 적용).
  8. 무전송 시험을 유지한 채 먼저 시험해. 실제 주문번호는 생성되지 않아. 실제 주문까지 원할 때만 공식 동의 2단계 및 최종 주문 자동 클릭을 켜고 무전송 시험을 끈 뒤 상세 내용을 확인하고 승인해.
  9. 영상처럼 PAYAPP까지 이동하고 싶을 때는 ⚡ 영상처럼 PAYAPP 결제 페이지까지 자동 이동을 별도로 선택해. 무전송 시험이 꺼지는 실제 주문 모드이므로 경고창을 읽고 승인해야 해. 주문번호 확인 후 공식 결제하기 버튼을 최대 1회 클릭해. 크롬 팝업 차단으로 새 창이 안 열릴 수 있고, 결제는 직접 승인해야 해.
  10. 결과는 도우미 아래 ⏱️ 자동주문 구간별 속도 기록에서 확인해. 복사하거나 JSON으로 저장할 수 있어.

📱 갤럭시 크롬: 베베픽 페이지에서 주소창에 베베픽 실행이라고 입력한 후 아래 표시되는 🔖 북마크 추천 항목을 눌러 줘. 일반 북마크 목록에서 열면 JavaScript가 실행되지 않을 수 있어. 반드시 북마크 주소가 javascript:로 시작해야 해.

① 베베픽 실행 북마크 (필수 · 짧은 코드)

② PAYAPP 전체동의 → 다음 보조 북마크 (선택)

이전과 달리 PAYAPP 동의라는 별도 북마크로 만들어 줘. PAYAPP 화면에서만 사용하고 약관을 읽고 승인한 뒤 실행해. 결제수단·카드번호·최종 승인은 수동이야.

③ 북마크 실행 확인용 (진단)

베베픽 실행 북마크가 여전히 반응이 없다면 베베픽 진단이라는 새 북마크에 아래 코드를 넣고 주소창에서 이름 검색 → 북마크 추천을 선택해. 확인 창이 뜨는지로 크롬 실행 문제를 구분해.

🗃️ 자동주문 기록 자동 저장: 대기 시작부터 300ms 단위로 진단 기록을 브라우저 저장 공간에 보관하고, 최근 8번의 기록을 PAYAPP 이동 또는 탭 종료 후에도 남겨. '⏱️ 자동주문 구간별 속도 기록'을 펼쳐 지난 기록 보기·복사·JSON 저장·삭제를 할 수 있어. 채널별·브라우저별 저장이며 로그인을 바꾸거나 Chrome 데이터를 삭제하면 사라질 수 있으니 중요한 기록은 JSON 파일로 보관해. 카드/주문번호/주소는 기록하지 않아. '네, 이대로 주문' 대기 및 중단 시 체크박스/버튼 활성 여부도 구조 정보만 기록해.

안전장치: 무전송 시험 기본 · 미래에 어느 이름 후보가 선택될지 모른다는 점을 실주문 승인창에서 고지, 수량/재고/장바구니 재검증, 주문 1회 클릭·중복 방지. 기존 주문의 보관/배송 방식 변경 경고나 사이트 제한이 감지되면 자동 중단. PAYAPP 이동은 기본 OFF이며 명시 동의가 있어야 공식 버튼을 최대 1회 클릭해. PAYAPP 화면의 어떤 결제 승인 버튼도 누르지 않아. 로그의 DOM 클릭 기록은 주문 접수 성공을 의미하지 않아.

실주문 모드에서 주문번호가 생성되면 3분 결제 기한이 시작될 수 있고, 미결제나 결제 후 취소에 따른 제한 가능성이 있어. 모든 후보를 실제로 구매할 의사가 있을 때만 실주문을 켜 줘. 결제 직전 화면이 나오면 도우미 창을 자동으로 접고 공식 결제 버튼 쪽으로 스크롤해. 크롬 창 자체를 운영체제 작업표시줄로 최소화하는 기능은 아니야. 백그라운드에서는 안전상 감시/확인 동작이 중지될 수 있어. 실제 사이트의 접근 제한을 우회하지 않으며, 저장된 주문 생성 전에는 구매가 완료된 것이 아니야.

속도 로그는 같은 브라우저의 해당 베베픽 채널에 최근 8회까지 자동 보관돼. 쿠키·인증 토큰·주문번호는 담지 않아.
